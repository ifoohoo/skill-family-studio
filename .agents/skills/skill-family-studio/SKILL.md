# Skill Family Studio 控制台技能

用户只需用自然语言提出“看设计、审需求、核对跨仓对齐、查任务推进树或看多智能体会话编队”，由你代劳探测环境、按需配置并打开 `127.0.0.1:57630`（或隔离端口）控制台。**严禁要求用户自己背命令行参数、猜测扫描目录或手写配置文件。**

## 一、交互式对话启动流程（必须严格按序执行）

### 第 1 步：先识别用户意图与默认目标页签

- 用户想“看全盘架构、依赖连线或 Archify 图” → `--tab graph`
- 用户想“审阅需求、故事、场景，或核对需求拆分与代码锁漂移” → `--tab review`
- 用户想“看长程任务推进树、派出去的子会话协同、文件锁或排障” → `--tab runtime`
- 仅泛指“打开工作台 / 新手看看” → 选 `graph`（若探测到高阶规划仓或上游绑定则选 `review`）

### 第 2 步：静默运行只读环境探针（严禁跳过）

在已激活项目要求的 Node.js 运行时环境中执行：

```bash
npx skill-family-studio inspect-setup --root <当前项目绝对路径> --json
```

根据探针返回的 JSON 字段采取对应动作：

1. **情况 A：独立单技能族仓且未绑定上下游（`needsUserChoice === false` 且非多仓父目录）**
   - 直接用单仓聚焦模式启动，绝不把父目录无关项目混入下拉框：
     ```bash
     npx skill-family-studio ensure --root <当前项目绝对路径> --scan-roots none --tab <目标页签>
     ```
2. **情况 B：已存在 `.studio-workspace.json` 或用户已明确要求全套组展示**
   - 按现有工作区边界启动（无需重复询问）：
     ```bash
     npx skill-family-studio ensure --root <当前项目绝对路径> --tab <目标页签>
     ```
3. **情况 C：存在关联上下游绑定或多仓父目录，且尚无 `.studio-workspace.json`（`needsUserChoice === true`）**
   - **只向用户提一个极简中文三选一问题**（严禁抛出一堆术语或配置文件参数）：
     > 检测到当前仓库关联了上下游（或同目录多个）仓库，希望怎么打开工作台？
     > 1. **只看当前这一个仓**（最清爽，不混入其他项目）
     > 2. **自动纳入关联的上下游仓**（可看需求进展与双向对齐总览表并一键跨仓互跳，顺便帮你写好 `.studio-workspace.json`）
     > 3. **扫描我自己指定的业务域目录**（你告诉我目录相对路径即可）
   - 用户选 `1` → 用 `--scan-roots none` 启动；
   - 用户选 `2` → 先执行 `npx skill-family-studio init-workspace --root <当前项目绝对路径> --mode related`，再执行 `ensure`；
   - 用户选 `3` → 代执行 `init-workspace --mode custom --scan-roots <dirs>` 后再启动 `ensure`。

> 注：`ensure` 会先核对目标端口既有的 `/api/studio/state` 是否已收录当前项目；已收录则自动带精确 `?repo=<id>` 复用，未收录则自动隔离分配新空闲端口，绝不张冠李戴。

## 二、向用户交付“明确、免抽样”的固定审阅路线

启动成功后，**必须**结合探针结果给用户一条直接可点、不用自己摸索的 3～4 步路线：

```markdown
### Skill Family Studio 已就绪
- **点击打开**：`<实际返回的 URL>`（`<复用当前项目视图 / 新建独立本地端口>`）
- **当前范围**：`<单仓聚焦 / 多仓套组（共 N 个关联仓）>` · 当前锁定 `<仓库标识>`

#### 建议按以下顺序查看（免自由抽样）
1. **第 1 步（看哪一页）**：`<依据本次目标，明确说明打开哪个页签和具体列表>`
2. **第 2 步（核对关键信息）**：`<例如：先看「📝 审阅与对齐」第 ① 步「① 核对需求与代码对齐」并点「下一步：开始逐篇审阅正文 →」/ 按「第 1 顺位：先看诉求（用户故事） → 第 2 顺位：核对边界（需求与场景）」逐篇阅读或点「▶ 跳至下一项待审条目 →」/ 看「⚡ 运行监控」→「🌳 任务推进树」与「🛰️ 智能体会话编队」（看到「🟢 无卡死」无需打开排障页）>`
3. **第 3 步（如何完成闭环）**：`<写批注点「＋ 添加批注（自动转入审阅中）」（未提交草稿跨篇自动暂存为「📝 草稿」），确认无误点「✓ 通过并审下一项 →」，最后点「③ 导出验收结论」或右上角「审阅进度：... 导出 ▾」导出验收单；图谱与术语随时悬停或点击 ⓘ 查看说明>`
```

## 三、职责与安全红线

- **只读受审仓，零侵入落盘**：批注与审阅结论只写入工作台启动根目录的 `.skill-family-studio/reviews.json`；除用户确认生成 `.studio-workspace.json` 外，绝不修改兄弟仓任何 Git 跟踪文件。
- **回环纯离线与脱敏**：服务仅监听 `127.0.0.1`，全部前端资源与图示纯本地运行；多智能体会话编队监控严格只读、脱敏路径与密钥，绝不读取 `.ssh` / `.env` 等敏感目录。
- **不越权 Git 写操作**：本技能不执行 `git commit`、`git push`、`git tag` 或包发布。
